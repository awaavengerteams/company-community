# ทำไมต้องตั้ง region เป็น sin1

## ปัญหาที่วัดได้

Vercel ตั้ง function region เริ่มต้นเป็น `iad1` (เวอร์จิเนีย สหรัฐฯ)
แต่ผู้ใช้และฐานข้อมูลอยู่ในเอเชีย — ทุก request จึงข้ามแปซิฟิกไปกลับ

```
x-vercel-id: sin1::iad1::…
             ↑      ↑
        edge สิงคโปร์  function เวอร์จิเนีย ← ตัวปัญหา
```

เส้นทางเดิมของ request เดียว:

```
ไทย → edge สิงคโปร์ → function เวอร์จิเนีย → Supabase เอเชีย
                    ←                     ←
```

ข้ามมหาสมุทร **2 รอบ** ต่อ 1 request ทั้งที่ต้นทางกับปลายทางอยู่ห่างกัน ~1,500 กม.

## ตัวเลขที่วัดได้จริง

| วัดอะไร | เวลา |
|---------|------|
| เครื่อง → Supabase ตรง ๆ | **0.17s** |
| เครื่อง → Vercel edge (sin1) | **0.21s** |
| เครื่อง → `/api/time` (ผ่าน function ที่ iad1 แล้วคุย Supabase) | **0.63s** |

ส่วนเกิน ~0.45s ต่อ request คือค่าเดินทางข้ามแปซิฟิกล้วน ๆ

หน้าห้องเรียก API หลายตัวตอนเปิด (bootstrap + วัดนาฬิกา 3 ครั้ง)
ความหน่วงจึงทบกันจนรู้สึกช้าชัดเจน

## แก้

`vercel.json`:

```json
{ "regions": ["sin1"] }
```

ตอนนี้ function รันที่สิงคโปร์ซึ่งอยู่ใกล้ทั้งผู้ใช้และ Supabase

## ★ ผลข้างเคียงที่ต้องรู้

Vercel **Hobby จำกัด 1 region** ถ้าอยากให้เร็วทั่วโลกต้องใช้ Pro แล้วใส่หลาย region
แต่ถ้าผู้ใช้ส่วนใหญ่อยู่ไทย การตรึงไว้ที่ `sin1` ดีกว่า `iad1` แน่นอน

## เรื่อง timezone — ไม่เกี่ยวกับความเร็ว

ระบบนี้ไม่ได้รับผลจาก timezone เลย เพราะ:
- `started_at` เก็บเป็น `timestamptz` (UTC) ในฐานข้อมูล
- การคำนวณตำแหน่งเพลงใช้ epoch milliseconds ล้วน ๆ
- ไม่มีที่ไหนแปลงเวลาเป็นเขตเวลาท้องถิ่น

★ ตั้ง `TZ` บน Vercel ไม่ได้ — เป็น env สงวนที่ถูกบังคับเป็น UTC เสมอ
(`Error: The following environment variables can not be configured: TZ`)

ซึ่งไม่เป็นปัญหาเลย เพราะระบบไม่ได้พึ่ง timezone ของ runtime
